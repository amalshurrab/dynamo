# Report, summary and deck structure

Source: Mathkor reports 17/18 Nov 2026 (`reports/2026-11-18/report.html`), the CEO summary, and the Thursday deck
«مذكور في ثلاثة أيام» (2026-11-19). last_verified: 2026-11-19

## Detailed management report (A4 or 1600×1060, 8–12 pages)
1. Cover: venture logo, title «تقرير العمل: <venture>», date, one line of scope. No "prepared by/for" meta line.
2. Summary page: 3–6 KPI tiles (files, pages, posts, days) + a status table (area / state / note).
3. One page per theme (identity, social, publishing, website, developer handoff…): what was done with numbers, a real
   screenshot with a caption, files delivered, verification done.
4. Open items: table with item, owner, date. Only what is still needed.
5. Footer on every page: venture name, date, page number; logo small.
Style: Cairo, venture colours, numbers in Inter LTR inside RTL text, tables not paragraphs, no adjectives.

## One-page CEO summary
Logo, title, date, 6–10 short lines of outcomes (what is live, what is scheduled, what is decided), 2–3 open decisions
with owner. No technical detail, no file paths, no numbers that need explanation.

## Team meeting deck (studio weekly meeting)
- Audience = the team; purpose = show what automation did and saved. One idea per slide, big numbers, real screenshots,
  venture theme, animated self-playing scenes when asked (no click-step reveals). No "next steps" and no lessons slide
  unless asked. Cover text short; no team chips or URLs on the close.
- Shape that worked: cover → comparison (traditional weeks vs days) → team → the work in 4 slides with real images →
  count-up numbers → close.
- Export: see skills/report-pdf (screenshot each slide, bind PNGs).

## Artefact-consistency pass after a decision
List every artefact that carries the old value (plan doc, execution doc, deck source + PDF, Lean Canvas UVP/channels,
venture details on Flow OS, social bios, venture profile) → update each → re-export PDFs → report the list with dates.
