# Flow OS surfaces and management-reader rules

Source: One Studio Flow OS usage 2026-11 (ventures `onestudio`, `lead-ai`), reviewer rules recorded in memory files
`daily-update-style`, `deck-style`, `mathkor-copy-rules`. last_verified: 2026-11-19

| Surface | Where | Format | Gate |
|---|---|---|---|
| Daily update | studio venture (`onestudio`, not `one-studio`) | `@alaa-saqer` first line; `- [x]` done / `- [ ]` next; one formal MSA fact per line; tags `#daily-update #<venture>` | draft → reviewer yes |
| Venture update post | the venture (`lead-ai`) | formal MSA, a title, 3–8 lines, no names, no emojis | reviewer yes; reviewer may reject a topic |
| Big Shift card | `log_big_shift_card`, one "automated" + one "vo_step" card per person | ≤500 chars, editable until Thursday 10:00 Riyadh; after that it saves to the next week | reviewer yes |
| Issue | the venture | title, context, acceptance criteria, owner, due date, priority; evidence links | reviewer yes |
| Lean Canvas / venture details | the venture | UVP, channels, name, tagline, colour, avatar | reviewer yes |
| Stage rules | the venture | evidence per exit rule (problem memo with external "why now", buyer count with source, top-3 risky assumptions with dated tests) | reviewer yes |

Reader rules: the CEO wants short lines and the logo; the decision maker is the manager, not the marketer; never name a
third person as a decision owner unless the profile says so; never use the words "Thursday deck".
